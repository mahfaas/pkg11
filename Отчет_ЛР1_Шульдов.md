## Цель работы

Целью работы является изучение цветовых моделей RGB, XYZ и HLS, методов перехода между ними и исследование цветового графика МКО (CIE 1931), а также разработка интерактивного веб-приложения для задания, изменения и отображения цвета одновременно в трёх цветовых моделях. Приложение должно позволять задавать точные значения компонентов, выбирать цвет с помощью графической палитры и плавно изменять его ползунками. При изменении любой координаты остальные представления цвета должны автоматически пересчитываться. Также должна выполняться проверка допустимых диапазонов и выводиться предупреждение при необходимости ограничения рассчитанного значения.

## Ход работы

В ходе работы были изучены цветовые модели RGB, XYZ и HLS, их компоненты, диапазоны значений и особенности представления цвета. Для выбранного варианта были рассмотрены преобразования RGB ↔ XYZ и RGB ↔ HLS. Переход между XYZ и HLS выполняется через промежуточную модель RGB. Для преобразования RGB и XYZ используются стандартные алгоритмы цветового пространства sRGB с учётом белой точки D65.

Также в теоретической части работы был исследован цветовой график МКО (CIE 1931). Были рассмотрены его назначение, принцип построения и связь с цветовым пространством XYZ, а также особенности представления цветности на графике в координатах xy.

Практическая часть заключалась в разработке веб-приложения с тремя основными блоками: RGB, XYZ и HLS. Для каждой компоненты предусмотрены числовое поле и ползунок. Также реализована интерактивная HSV-палитра на основе HTML Canvas. В палитре две координаты цвета задаются непосредственно в графической области, а цветовой тон H (Hue) изменяется отдельным ползунком. Дополнительно отображаются текущий цвет и его значение в формате HEX.

Приложение позволяет задавать цвет тремя способами: точным числовым вводом, выбором с помощью HSV-палитры и изменением компонентов с помощью ползунков. При изменении любой координаты приложение автоматически пересчитывает значения в двух других цветовых моделях и обновляет отображаемый цвет.

Структура приложения разделена по принципу Model–View–Controller (MVC):
- **Model** (`js/model.js`) отвечает за хранение цветовых значений и выполнение преобразований RGB, XYZ и HLS. Реализует паттерн «Мост» (Bridge): абстракция `ColorModel` (публичный API) отделена от реализации `ColorModelImpl` (математика). Это позволяет изменять алгоритмы конвертации независимо от интерфейса.
- **View** (`js/view.js`) отвечает за отображение данных, работу полей ввода, ползунков, HSV-палитры и цветового графика МКО. Не содержит математических формул.
- **Controller** (`js/controller.js`) обрабатывает действия пользователя, передаёт данные между Model и View и запускает необходимые пересчёты.

Для связи компонентов реализован паттерн «Слушатель» (Observer) через `ColorEventBus`. Model испускает событие `colorChanged` при каждом изменении цвета; Controller и View подписываются на это событие и обновляют интерфейс. Это обеспечивает полное разделение слоёв: Model не знает ни о View, ни о Controller.

Для обработки некорректных цветов реализована проверка диапазонов. Например, при преобразовании XYZ → RGB рассчитанное значение может выйти за допустимый диапазон sRGB 0–255. В этом случае значение ограничивается соответствующей границей (clipping), а пользователю выводится ненавязчивое предупреждение о выполненном ограничении.

## Реализованные преобразования

### RGB ↔ XYZ

Матрица перехода строится динамически по методу Брюса Линдблума из хроматичностей праймериз sRGB (R: 0.64/0.33, G: 0.30/0.60, B: 0.15/0.06) и координат белой точки D65 (x=0.31271, y=0.32902). Применяется гамма-коррекция sRGB:

```
γ-коррекция → линейный RGB:
  c ≤ 0.04045  →  c / 12.92
  c > 0.04045  →  ((c + 0.055) / 1.055) ^ 2.4

Линейный RGB → γ-коррекция:
  c ≤ 0.0031308  →  c * 12.92
  c > 0.0031308  →  1.055 * c^(1/2.4) − 0.055
```

### RGB ↔ HLS

Стандартные секторные формулы по максимальному и минимальному каналам нормированного RGB ∈ [0, 1]:

```
max = max(R,G,B),  min = min(R,G,B),  d = max − min
L = (max + min) / 2
S = d / (1 − |2L − 1|)    (при d ≠ 0)
H — угол [0°, 360°) по доминирующему каналу
```

Переход XYZ ↔ HLS выполняется через RGB: XYZ → RGB → HLS и обратно.

### Цветовой график МКО (CIE 1931)

На графике отображается диаграмма хроматичности CIE 1931 в координатах xy. Каждый пиксель внутри спектрального локуса окрашивается по координатам xy (при Y=1) через матрицу XYZ→sRGB. Текущий цвет отображается маркером; пунктирная линия соединяет его с белой точкой D65.

## Выводы

В ходе лабораторной работы были изучены цветовые модели RGB, XYZ и HLS, реализованы преобразования между ними и исследован цветовой график МКО CIE 1931. Были рассмотрены особенности цветовых пространств, способы задания цветовых координат и принципы преобразования между выбранными моделями.

Создано интерактивное веб-приложение, позволяющее задавать цвет числовыми полями, с помощью HSV-палитры с двумя координатами в графической области и отдельным ползунком тона, а также изменять его компоненты ползунками. Реализован автоматический пересчёт цвета во всех трёх моделях при изменении любой координаты и обработка выхода рассчитанных значений за допустимые диапазоны.

Разделение приложения на Model, View и Controller с применением паттернов «Мост» (Bridge) и «Слушатель» (Observer) позволило отделить математические преобразования от пользовательского интерфейса и обеспечить слабую связанность компонентов. Таким образом, основные требования технического задания по реализации трёх способов задания цвета, автоматическому пересчёту, преобразованию цветовых моделей, исследованию графика МКО, удобству интерфейса и обработке некорректных значений выполнены.
